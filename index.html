手把手教你部署 Claude Code + DeepSeek + LiteLLM：Windows 11 实战教程

发表于 2026-10-11 分类于 学习经验

一、项目介绍

Claude Code 是一款面向编程任务的 AI 工具，可以帮助开发者阅读代码、修改项目和执行开发任务。

DeepSeek 提供了可通过 API 调用的模型。通过配置兼容接口，可以尝试让 Claude Code 使用 DeepSeek，而不一定要直接使用 Anthropic 的模型服务。

不过，如果以后还想在 DeepSeek、Claude、OpenAI 等不同模型之间切换，每次修改客户端配置就不够方便了。

因此，本教程准备搭建以下架构：

LiteLLM 负责统一接收请求，并将请求转发给对应的模型提供商。需要注意：如果后端使用云端 API，模型推理仍然在云端进行，本地运行的是网关服务。

本文目标：

  1. 安装 Claude Code。
  2. 验证 Claude Code 可以直接调用 DeepSeek。
  3. 准备 LiteLLM 网关配置。
  4. 使用 Docker 运行 LiteLLM。
  5. 让 Claude Code 通过本地网关调用模型。
  6. 为后续扩展其他模型提供商做好准备。

说明：本文的前两步已经在实际环境中验证。由于当前 Windows 11 的虚拟机平台功能尚未成功启用，Docker 和 LiteLLM 的最终启动及端到端调用仍需完成验证。

十一、部署完成后应该如何验证？

由于本次部署停在 Docker Engine 无法启动的阶段，下面这些属于后续验证步骤，尚未在本次环境中完成。

1. 验证虚拟机平台

确认功能已启用，并按系统提示完成必要的重启。

2. 验证 Docker Engine

确认 Client 和 Server 均能正常返回信息。

3. 启动 LiteLLM

重新执行前面的 docker run 命令，观察容器日志，确认服务正常启动。

4. 验证网关 API

当 LiteLLM 成功启动后，可以先通过其模型列表接口检查服务：

如果服务正常，应该能够得到模型列表响应。若返回认证错误，需要检查网关密钥；若连接失败，需要检查容器是否正在运行、端口映射是否正确。

5. 配置 Claude Code 指向本地网关

只有在网关已经成功启动、模型别名已配置且 API 调用验证通过后，再将 Claude Code 的接口地址改为本地 LiteLLM 地址，并配置网关密钥与模型别名。

这一步应根据当前 LiteLLM 版本的 Claude Code 接入文档完成，不能仅凭变量名称猜测兼容性。

十二、总结

这次实战已经验证了 Claude Code 直连 DeepSeek 的基本流程，也完成了 LiteLLM 配置文件的初步准备。

但 Docker Desktop 受 Windows 11 虚拟机平台启用问题阻塞，导致 LiteLLM 尚未成功启动。因此，目前不能把整个部署描述为已经完成。

本次最值得总结的经验有三点：

  1. 分层验证：先验证 Claude Code 与 DeepSeek，再验证 Docker，最后验证 LiteLLM 网关，避免混淆问题来源。
  2. 重视修复源匹配：DISM 报错时，应结合当前系统构建版本、映像版本和组件需求分析。
  3. 用日志收敛原因：进度停滞和操作取消都是线索，但必须结合上下文才能判断根因。

后续应先解决 Windows 组件获取和 VirtualMachinePlatform 启用问题，再完成 Docker、LiteLLM 与 Claude Code 的端到端验证。届时可以继续补充实际成功的网关调用结果和多模型切换示例。
